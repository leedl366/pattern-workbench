# 架构与运行参数

> 以下数值取自已上线的生产站（2026-11-19 实测）。

## 一、进程与端口

| 项 | 值 |
|---|---|
| 工作目录 | `/opt/pattern-workbench/app`（改成你本机路径即可） |
| 启动命令 | `venv/bin/uvicorn server:app --host 127.0.0.1 --port 17700` |
| 监听 | **127.0.0.1:17700**（只监听本机，外网由反代进来） |
| 进程管理 | systemd 单元 `pattern-workbench` |
| 环境变量 | `PYTHONUNBUFFERED=1` |
| 解释器 | Python **3.10.12** + venv（唯一；系统 python 没有 fastapi） |
| 日志 | `journalctl -u pattern-workbench -n 100` |

## 二、反向代理

线上把 `/pattern/` 前缀**剥掉**再转给 17700（所以应用内部路由不带 `/pattern`）。
换机器时两种做法都行：

- **同构**：反代 `handle_path /pattern/* → 127.0.0.1:17700`（剥前缀）
- **简化**：直接访问 `http://127.0.0.1:17700/`，此时前端按相对路径取值，无需改代码

## 三、子应用挂载表（server.py）

| 挂载点 | 代码位置 | 加载方式 | 失败影响 |
|---|---|---|---|
| `/wm` | `wm/app.py` | `app.mount("/wm", wm_app)` | 仅去水印板块 |
| `/duotu` | `duotu/server.py` | **WSGIMiddleware** 包 Flask，`importlib` 从 `BASE/duotu/server.py` 动态加载 | 仅多图编辑板块 |
| `/hd` `/dtl` `/aigc` `/fk` `/swap` | 各目录 `app.py` | `app.mount()` | 各自板块 |
| `/deliver` | `deliver/` | StaticFiles(html=True) | 交付页 |
| `/pt` | 无独立目录 | 由 `server.py` 自身路由处理 | — |

所有 mount 都在 `try/except` 里：**单个子应用挂不上不影响主服务启动**，日志里会打印 `[xxx] 子应用挂载失败`。

## 四、部署链路（git 推送即上线）

```
本地 app-git ──git push──> <your-host>:/opt/pw-git/app.git （裸仓库，receive.denyNonFastForwards=true）
                                   │  post-receive 钩子
                                   ▼
                    /opt/pattern-workbench/app（检出 + 重启 systemd）
```

- 成功标志：`remote: [deploy] ✅ pattern-workbench 运行中`
- 钩子会先把服务器上的手改文件归档到 `/opt/pw-git/dirty-archive/<时间戳>/`，再同步
- 钩子内必须 `unset GIT_DIR GIT_WORK_TREE GIT_INDEX_FILE` 再 `export GIT_DIR=$WORK/.git`；钩子文件必须是 **LF**
- `force push` 被服务器拒绝（不是配置错误，是故意的）

**换句话说：`git push origin master` 就是上线。改生产前先在本机跑通。**

## 五、计费与账户

- 账户：`accounts.py` + `data/accounts.db`（SQLite WAL），三张表 `users / sessions / ledger`
- 会话：Cookie `st_session`，30 天
- 计费入口：`amount_for(rule, body, uid)` —— 由主站中间件按 `body["n"]` 计算张数，**管理员返回 0**
- 规则名示例：`dtl_gen` / `dtl_redo` / `fk_redo` / `swap_gen` / `swap_redo`（各 3 分/张）
- 🔴 **AI 接口一律收 JSON 而非 multipart**：中间件靠 `json.loads(body)["n"]` 数张数，multipart 解析失败会得到 n=0 → 不扣分（白嫖）

## 六、站点调度（ai_sites.py）

- 三线分流：`t2i`（0 张参考图）/ `i2i`（1 张）/ `multi`（≥2 张），入口 `lane_for(n)`
- `gen_image` 里参考图数量：`n_ref = len(imgs) if imgs else (1 if image_b64 else 0)`（**位置参数也算 1 张**）
- 各站点在 `ai_sites.json` 里配 `enabled / key / base_url / protocol`，后台可改、即时生效
- 熔断：`break_n=2` 次失败后 `break_sec=300` 秒内不再试
- 记忆：成功站点按线记忆（`_LAST_OK_BY_LANE`），**给了 lane 就绝不回落全局**

## 七、样式体系（要改 UI 必读）

- **唯一令牌源**：`static/ui.css` 的 `:root`。所有页面靠 `var()` 吃它
- 🔴 `dtl/fk/aigc/swap` 四页**各自带一份 `:root` 兜底块，位置在 `<link ui.css>` 之后** —— 同权重后者胜，改令牌必须同步这 4 份
- 🔴 `hd` 与 `wm` **不 link ui.css**，各自 `:root` 全套自带
- 🔴 11 个页面的 ui.css 引用已从「COS 直链优先 + onerror 兜底」改为**只读站内** `../accounts/static/ui.css`。**不要再加回 CDN 直链**，否则改主题不生效（COS 上是旧版且一直 200，onerror 永不触发）
- 没有 npm / Tailwind / 构建链，全部原生 HTML + CSS + JS

## 八、清理与 TTL

- 图案提取：主站 `data/<tid>/` + 定时清理
- 各子应用：`<mod>/data/records/` 与 `output/`，**72h TTL**
- 清理线程与「进行中」任务的判据必须是「本进程有活线程」，不是「记录写着 running」，否则会杀活任务
